# Initial fork validation — 2 November 2026

Scope: local Linux/x86-64 development delivery, based on upstream v0.2.1.
The owner selected the light portfolio layout and detailed task view, with
dark mode and responsive navigation. This is development integration, not a
tagged release or upstream acceptance.

- Rust formatting, Clippy with warnings denied, and 40 native tests passed.
- A release binary passed seven synthetic HTTP/MCP acceptance groups covering
  persistence, hierarchy/dependencies/cycles, dates, timers/idempotence, review
  acceptance, selected context, MCP discovery/calls and Host/Origin rejection.
- Meaningful native boundaries include migration without fabricated history,
  unknown-project review, sticky acceptance requirements, old-connection write
  refusal, parent/child invalidation, bounded history with full effort totals,
  persistent timers and oversized snapshot rejection.
- Browser acceptance used a disposable board at desktop1440×1000,
  tablet768×1024 and phone390×844. Light/dark, navigation, task descriptions,
  real child creation, saved dates, summary milestones, manual/timer time,
  context editing/copy and review acceptance were exercised.
- Browser regressions checked wrapped phone headers, theme/dialog task
  preservation, end-only schedules, per-task evidence drafts and a rejected
  parent acceptance retaining a usable retry action.
- Public-source preflight covered the selected source/document files for
  private host paths, key material and common token patterns. It is not a
  comprehensive secret, dependency-advisory or vulnerability scan.

Native phases used effective cgroup limits of two logical CPUs,4GiB RAM,
no swap and512PIDs with a ten-minute deadline. Disk/log growth had soft
watchdogs. The shared browser was not inside those build cgroups. Test boards
and services were task-owned; no test dates/hours/children were added to the
owner's live portfolio. Exact private evidence and rollback backups stay outside
the public source repository.

Observed QA failures were retained in private receipts, diagnosed and corrected;
the passing candidate was rebuilt after the final asset changes. These checks do
not establish Windows/macOS qualification, a production security certification,
remote CI success, unattended agent execution, or a causal learning benefit.
